# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Vanilla HTML/CSS/JS + Firebase SDK ผ่าน CDN (ไม่มี build step) — ตามแนวทางเดียวกับ [index.html](../index.html) และ [auction-app](../auction-app/index.html) ที่มีอยู่แล้วในโปรเจกต์นี้ (ยืนยันกับผู้ใช้แล้ว)

## Users

- **ผู้เข้าร่วม** (Trainer ในกิจกรรม) ~60 คน — ล็อกอินดูยอด token สะสมของตัวเอง + ประวัติแจก/หัก
- **วิทยากร/ผู้ดูแลกลุ่ม** ~20 คน — แจก token ให้ผู้เข้าร่วมระหว่างบรรยาย โดยกรอกรหัสประจำตัว
- **แอดมิน** (ทีมผู้จัดกิจกรรม) — ดูภาพรวมทั้งหมด ตั้งค่าโควตาวิทยากร หักยอดคืนประมูล จัดการบัญชีผู้ใช้

## Product Purpose

เว็บแอปแจก token ออนไลน์สำหรับโครงการ Training for the Trainers (TFT, 28 ก.ย.–2 ต.ค. 2569) มาแทนที่กลไกแจก token ด้วยมือ (กระดาษ/เหรียญ/สติกเกอร์) แบบเดิมทั้งหมด วิทยากรกดแจก token ให้ผู้เข้าร่วมได้ทันทีระหว่างบรรยาย ผู้เข้าร่วมล็อกอินดูยอดสะสมของตัวเองได้ตลอดโครงการ ยอดสุดท้ายใช้อ้างอิงตอนประมูลของรางวัลในงานเลี้ยงคืนวันที่ 4

## Positioning

ต่างจากแอปสะสมแต้ม/เหรียญรางวัลทั่วไปตรงที่ผู้เข้าร่วมไม่ได้สมัครบัญชีเอง (แอดมินสร้างบัญชีให้ล่วงหน้าด้วย username/password ชั่วคราว), วิทยากรแจกแทนผู้เข้าร่วมโดยกรอกแค่รหัสประจำตัว (ไม่ใช่ผู้เข้าร่วมกดรับเอง), และมีระบบ "โควตา" จำกัดจำนวน token ที่วิทยากรแต่ละคนแจกได้เพื่อป้องกันการแจกเกินจริง — เป็นเครื่องมือปฏิบัติงานสำหรับทีมจัดงาน ไม่ใช่แอปสาธารณะทั่วไป

## Operating Context

- ใช้จริงตลอดโครงการ 28 ก.ย.–2 ต.ค. 2569 ไม่ว่าบรรยายจะจัด onsite หรือ online
- ต้องมีอินเทอร์เน็ตตลอดการใช้งาน (backend Firebase) — ต่างจาก index.html คู่มือหลักและ auction-app ในโปรเจกต์เดียวกันที่ตั้งใจให้ทำงาน offline ได้ 100% เพราะแอปนี้ต้องให้วิทยากรหลายคนแจก token แบบเรียลไทม์และผู้เข้าร่วมหลายคนล็อกอินพร้อมกัน
- โน้ตบุ๊ก/มือถือของวิทยากรแต่ละคนต้องต่อเน็ตได้ระหว่างบรรยาย — ควรตรวจสอบสัญญาณในห้องบรรยายจริงก่อนวันงาน (auction-app เดิมเคยพบว่าสถานที่จัดงานสัญญาณเน็ตไม่แน่นอน)
- คืนวันที่ 4 (1 ต.ค. 2569) แอดมินหักยอด token ของผู้ชนะประมูลด้วยมือ พร้อมระบุรายการของรางวัลที่แลกไป — ไม่เชื่อมกับ [auction-app](../auction-app/index.html) แบบอัตโนมัติ
- ผู้เข้าร่วมมีทั้งหมด 7 กลุ่มสาขา (ตามโครงสร้างเดิมของ TFT)

## Capabilities and Constraints

- Backend: Firebase project `tft-e-token` (Firebase Authentication + Firestore) — ตัดสินใจแล้ว ไม่ใช่ทางเลือกเปิด
- Auth: username/password สร้างล่วงหน้าโดยแอดมิน ไม่มีการสมัครสมาชิกเอง — username pattern `tft01`–`tft80`, password ชั่วคราวเป็นตัวเลขสุ่มล้วนไม่เกิน 6 หลัก ผู้ใช้เปลี่ยนรหัสเองได้ภายหลัง (ไม่บังคับ)
- ต้องตั้ง Firestore Security Rules ห้ามผู้เข้าร่วมเขียนแก้ยอด token ของตัวเอง (เขียนได้เฉพาะฝั่งวิทยากร/แอดมิน) — ข้อกำหนดทางเทคนิคที่ต้องทำจริง ไม่ใช่ทางเลือก
- ระบบโควตา: วิทยากรแต่ละคนมี token ในมือจำกัด (เริ่มต้น 50 ปรับได้โดยแอดมิน) แจกแล้วหักจากโควตาตัวเอง ไม่ใช่หักจากส่วนกลาง
- ปุ่มจำนวนพื้นฐานสำหรับแจก: 1, 3, 5, 10, 15 + ระบุเอง; ปุ่มเหตุผลพื้นฐาน: "ตอบคำถาม", "ร่วมกิจกรรม" + ระบุเอง
- Audit trail: ทุกรายการแจก/หัก/ปรับโควตาบันทึกถาวร ยกเลิกด้วย `status: voided` เท่านั้น ไม่ลบทิ้งจริง แก้ไขย้อนหลังได้เฉพาะแอดมิน
- สเปกทางเทคนิคฉบับเต็ม (หน้าจอ/โครงสร้างข้อมูล/สิ่งที่ไม่ทำ) อยู่ที่ [SPEC.md](../SPEC.md) และขอบเขตงานที่ [SCOPE.md](../SCOPE.md)

## Brand Commitments

- ชื่อในแอป: ยังไม่กำหนดชื่อทางการ (ชั่วคราวเรียก "ระบบแจก e-Token — TFT") ผูกกับโครงการ TFT เดียวกับเว็บคู่มือหลักและ auction-app แต่เป็นเครื่องมือคนละชิ้นคนละกลุ่มผู้ใช้ — ไม่ใช้ระบบดีไซน์เดียวกับ DESIGN.md ของเว็บคู่มือหลัก (สงวนไว้เฉพาะเว็บคู่มือสาธารณะ) หรือ auction-app/DESIGN.md (สงวนไว้เฉพาะจอประมูลสด)
- แรงบันดาลใจด้านภาพ: ผู้ใช้ชี้ไปที่ artifact ส่วนตัวชื่อ "Token × Secret Buddy" (คู่มือ token สะสม + เกมจับคู่บัดดี้ลับของโครงการเดียวกัน) เป็นแรงบันดาลใจโทนสี/บรรยากาศ — ไม่ใช่ระบบดีไซน์ที่ต้องก็อปปี้เป๊ะ เป็นแค่แรงบันดาลใจ เพราะแอปนี้มีบทบาทผู้ใช้ (วิทยากร/แอดมิน กดแจก-หัก token จริงจากบัญชีจริง) ต่างจากคู่มือ/checklist สนุกๆ ของ artifact ต้นทาง

- artifact "Token × Secret Buddy" ที่ผู้ใช้ชี้ไปเป็น private artifact เข้าถึงได้เฉพาะผ่านเบราว์เซอร์ที่ล็อกอินของผู้ใช้เอง (ดึง CSS ดิบ/ทดสอบ interaction ไม่ได้เพราะถูก sandbox) — บันทึกไว้เฉพาะสิ่งที่สังเกตได้จากภาพหน้าจอจริง (hero, ระบบ token, ภารกิจ)

## Product Principles

- ความถูกต้องของยอด token มาก่อนความสวยงาม — ทุกการแจก/หักต้องตรวจสอบย้อนหลังได้เสมอ ไม่มีการลบข้อมูลทิ้งจริง
- วิทยากรต้องกดแจกได้เร็วกลางบรรยายโดยไม่สะดุด (กรอกรหัส → เลือกจำนวน/เหตุผลจากปุ่มลัด → ยืนยัน ไม่กี่ขั้นตอน)
- หน้าจัดการ (วิทยากร/แอดมิน) เน้นความจริงจังตรงไปตรงมา ส่วนหน้าที่ผู้เข้าร่วมเห็น (ดูยอดสะสม) คงกลิ่นอายสีสัน/playful ไว้ให้รู้สึกเป็นโปรเจกต์เดียวกับ TFT
- เป็นเครื่องมือปฏิบัติงานภายในทีมจัดงาน ไม่ใช่ผลิตภัณฑ์สาธารณะ — ไม่ต้องออกแบบให้ scale เกินความจำเป็นของงานนี้

## Accessibility & Inclusion

ยังไม่มีข้อกำหนดที่ยืนยันชัดเจน — ยังไม่ได้ถามผู้ใช้เรื่องนี้โดยตรง
